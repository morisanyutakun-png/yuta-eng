# 大学別 数学入試分析（yuta-eng.com）

国公立・私立 60 大学の数学入試について、出題形式・年度別の出題一覧・分野別の頻度をまとめた静的サイト。
各ページから、対応する教材（Amazon）へ導線を置いている。

## 構成

| パス | 内容 |
| --- | --- |
| `/` | 区分別の大学一覧と、学習段階から教材を選ぶ入口 |
| `/universities` | 全 60 大学の一覧（要約つき） |
| `/univ/[slug]` | 大学ごとの出題分析。主要な SEO 対象 |
| `/shindan` | 志望校診断模試 |
| `/kansei`・`/kansei/[slug]` | 分野別完成演習（シリーズと大学別） |
| `/books` | 教材一覧（全 89 冊） |

画面の幅で組み替える（モバイル用と PC 用に URL は分けない）。
読み物のページは `components/article-layout.tsx` が土台で、
広い画面のときだけ本文の横に袖（目次・購入導線）を出す。

全ページ `generateStaticParams` による静的生成。
クライアント JS は大学の絞り込み（`components/university-finder.tsx`）だけで、分析本文は送っていない。

## データの作り方

サイトの本文は、ホームディレクトリにある各予想問題集の原稿（LaTeX）の
「はじめに」＝出題分析セクションから機械的に起こしている。手書きの本文は持たない。

書名・価格・ページ数・発売日は原稿にないので、Amazon の商品ページから取り直す。

```
npm run data:books                 # 販売中の本（data/books.json）← Amazon
npm run data                       # 分析データ（data/analysis.json・manuscripts.json）
npm run data:series                # 過去問の前にシリーズ（data/series.json）
python3 scripts/build-covers.py    # 表紙画像（public/covers/*.webp）
python3 scripts/build-og.py        # OG画像とサムネイル
python3 scripts/build-series-assets.py  # 過去問の前にシリーズの表紙・OG
python3 scripts/build-samples.py   # 試し読みの抜粋（public/samples/）
npm run check                      # データの突き合わせ（公開前に流す）
npm run build && npm run check:html  # 出来上がった画面の点検（公開前に流す）
npm run check:solutions            # 掲載した解答を別の方法で解き直して確かめる
```

### 本を1冊足すとき

1. `scripts/book-registry.mjs` に `{ asin, series, slug, vol }` を1行足す
2. 新しい大学なら `scripts/university-meta.mjs` に原稿フォルダを登録する
3. `npm run data:books` → `npm run data` → 表紙・OG のスクリプト → `npm run check`

ASIN と大学の対応だけが手入力で、ほかは原稿と Amazon から機械的に作る。
`npm run check` は、価格・ページ数がサイトと Amazon でずれていないか、
表紙や OG 画像が欠けていないか、試験時間や配点が常識的な範囲かまで見る。
`npm run check:html` はビルドした HTML を読んで、id の重複・見出しの飛び・
title や description の欠け・リンク切れ・組み残した数式がないかを見る。
本番に出してからでないと気づきにくいものを、ビルドの時点で止めるため。

### 原稿フォルダの見分け方

どの大学のフォルダにも、雛形として名大の巻（`名大数学vol1` など）がコピーされている。
フォルダ名では見分けられない（`名大文系数学` の中にも名大理系の巻がある）ので、
「はじめに」の見出しが**ほかの大学の名前**になっている巻を落としている。
巻の対応づけの結果は `data/manuscripts.json` に書き出し、表紙の切り出しでも同じものを使う。

表紙は各原稿の `cover.pdf`（表1＋背＋表4の一枚もの）から、
表紙の部分だけを切り出して WebP にしている。背幅はページ数で変わるので、
「右の裁ち落としを除いて判型の幅ぶんを右から取る」ことで背幅に依存せず切り出す。
PyMuPDF と Pillow が必要（`pip install pymupdf pillow`）。

`build-og.py` は大学ページの OG 画像（1200×630・`public/og/<slug>.jpg`）と、
一覧に並べる小さい表紙（`public/covers/thumb/<ASIN>.webp`）を書き出す。
OG の書体は原稿の組版と同じ Harano Aji（TeX Live 同梱）を使うので、
表紙と字面が揃う。TeX Live が別の場所にある場合は `FONT_DIR` を直すこと。

- 入力
  - `~/KDP_app/scripts/data/product-list.csv` … 書名・ASIN・価格・原稿PDFのパス
  - `~/<原稿フォルダ>/front.tex` … 各巻の「はじめに」
- 対応づけ … `scripts/university-meta.mjs`（原稿フォルダ → slug・大学名・区分）
- 出力 … `data/analysis.json`（リポジトリにコミットする）

原稿はリポジトリの外にあるため、`data/analysis.json` は**生成物をコミットしておく**。
Vercel 上のビルドでは再生成されない。原稿を直したら手元で `npm run data` を実行して
差分をコミットすること。

### 抽出時にしていること

- LaTeX のインライン（`\textbf` `\underLine` `$…$` ほか）を span 配列へ
- **平文フィールドは数式を文字に落とす**（`spansToPlain`）。原稿は「配点は `$100$` 点」
  「3完+`$\alpha$`」のように数字まで数式にしているので、要約・目標点・見出し・分野名に
  `$…$` のまま入れると生の LaTeX が画面に出る。逆に丸ごと削ると数字が消える。
  数字・ギリシャ文字・簡単な記号だけの式は文字に直し、分数や添字つきの式は落とす
- `tabular` / `longtable` を表に、`enumerate` / `itemize` を箇条書きに
- 「本書では〜」など**書籍の中身に触れる文・行・列は落とす**（サイトでは意味をなさないため）。
  括弧書きだけを外して周りの分析文は残すよう、文字単位で判定している
- 全角カンマ・ピリオド（，．）を読点・句点に直し、LaTeX の改行由来の空白を詰める
- 試験時間・大問数・解答形式・配点を導入文から拾って `facts` に、
  分野別頻度の表を棒グラフ用の `fieldChart` に、目標点の一文を `goal` に
- **配点は数学のぶんだけを採る**。導入文には「数学250点・外国語250点の計500点」のように
  他教科との合計が混ざるので、`数学◯点` と名指しされた数か、他教科名の出てこない文の数だけを使う。
  候補が2つ以上に割れたら（学部で配点が違うなど）出さない
- **選択制の大学は大問数を出さない**（`facts.selective`）。千葉大・新潟大・愛媛大は
  1冊の冊子から志望学部ぶんだけを選んで解くので、冊子の題数と解く題数が一致しない
- **年度は年度別出題一覧から数える**。見出しの「（2019--2026年度）」は実際に載っている表と
  食い違うことがあるため、表があれば表を正として `years` と `yearCount` を決める
- **分野別グラフの分母は「題数で数えた表」のときだけ出す**（`fieldChart.kind`）。
  見出しが「8年中」の表に並ぶ数字は年数ではなく題数なので、分母として扱うと
  「微分積分 16 / 8年」のような表示になる
- 予想問題の**収録回数と別解の有無は巻ごとに数える**（`set1_q.tex` の数、`betsu` 環境の有無）。
  多くは5回だが防衛医科大は6回、千葉工大は8回で、別解のない巻もある
- 数式は `lib/render.tsx` でビルド時に KaTeX で HTML 化（クライアント JS を増やさない）

複数巻ある大学は、分析がいちばん充実している巻を代表として本文に使い、
CTA には全巻を並べる。

## 「過去問の前に」シリーズ（志望校診断模試・分野別完成演習）

| パス | 内容 |
| --- | --- |
| `/shindan` | 旧帝大・難関国公立大理系数学 志望校診断模試 |
| `/kansei` | 大学別 分野別完成演習のシリーズ一覧 |
| `/kansei/[slug]` | 大学ごとの分野別完成演習。slug は大学別分析（`/univ/[slug]`）と同じ |
| `/books` | 教材一覧 |

サイト全体を「志望校未決定 → 志望校診断模試 → 分野別完成演習 → 合格答案をつくる」の
学習段階で並べている（`components/learning-path.tsx`）。順番は原稿の記述どおり。
分野別完成演習の導線は、対象の8大学（診断模試の判定対象と同じ）の分析ページにだけ出す。

```
npm run data:series                    # 原稿 → data/series.json
python3 scripts/build-series-assets.py # 表紙（public/covers/kansei/）と OG 画像
```

- 中身は各巻の原稿（`~/<大学>/…完成演習/front.tex`・`chN_q.tex`・`appendix.tex`、
  `~/難関国公立診断模試/診断模試2027/front.tex`・`sougou.tex`）から起こす。原稿は読むだけ。
  問題文・解答は取り出さず、「はじめに」と章扉（分野・出題傾向・収録問題の題材名・目標時間）だけを使う
- 抽出時に、原稿の中の3か所（2.1節の章の表・章扉の問題一覧・表紙）で題数・レベル内訳・目標時間・
  小問数・数学III前の章が一致するかを照合し、ずれていれば「要確認」を出して終了コード 1 にする
- LaTeX のパーサは `scripts/lib/latex.mjs` に切り出し、大学別分析の抽出と共通にしている
- Amazon の商品情報（ASIN・価格・ページ数・発売日・ISBN）は合格答案をつくると同じく
  `scripts/book-registry.mjs` と `data/books.json` で持つ。原稿には書名も値段もない
- 原稿は8大学ぶん用意してあるので、まだ出していない巻も `data/series.json` には入っている。
  `book-registry.mjs` に ASIN を足した巻だけがページになる（`lib/series.ts` の `kanseiPublished`）

## 試し読み（抜粋）

書店での立ち読みに近い範囲で、書籍の中身を見られるようにしている。
`scripts/build-samples.py` が本文PDFから1冊あたり4〜6ページを抜き出し、
画像（`public/samples/<ASIN>/p1.webp`…）と、同じ抜粋だけを集めたPDFを作る。

- **原稿・本文PDFは読むだけ**。公開ディレクトリに置くのは抜粋した画像とPDFだけで、
  本文まるごとのファイルは配信しない
- 抜き出すのは **試験の扉1・問題2・解答1** の4ページ（診断模試だけ診断ページを1枚足す）。
  目次・本書の使い方・採点基準は入れない。中身の手ざわりが伝わるのは扉と問題なので、そこを厚くする
- 扉は目次のページ番号より1つ手前にあることがある（ノンブルを持たない扉）。
  1つ前のページがその回の扉なら、そちらを採る。ページ番号のないページは番号を出さない
- **扉・問題・解答は、わざとすべて別の回（章）から採る**。
  同じ大問の「問題・解答・詳解・採点基準」が一式そろって見えないようにするため。
  ひとつの回から2ページ以上出さないことも含めて、`npm run check` で毎回確認している
- 問題が実質1ページに収まっている回（文系の本など）は、1枚出すとその回の問題が丸ごと見える。
  そういう回は多くても2つまでにする
- 問題のページは、候補のうち分量が中くらいのものを選ぶ
  （1行問題だけの余白だらけのページも、最も詰まったページも代表的でないため）
- 版の取り違えを防ぐため、**表紙ページの巻表示（Vol.N／第N巻）が一致する本文PDF**だけを使う。
  ページ数も Amazon の表示と突き合わせ、2ページまでの差は同じ版として扱って報告する
  （KDP の表示が組版と少しずれている巻がある）
- 画面では `components/look-inside-section.tsx`（見出し・断り書き・購入リンク）と
  `components/look-inside.tsx`（拡大表示）が担当する。抜粋のない本では何も出さない

## 過去問の解答・解説（/kaisetsu）

過去問について、**こちらで独自に解いた解答・計算過程・詳解・別解だけ**を公開する。

### 考え方

入試問題の著作権は各大学にある。大学が「2次利用には出所明示と利用報告書を」と
条件を付けているのは、**その問題を複製・公衆送信する人**に向けたもの。
このサイトは問題を1文字も載せないので、複製も公衆送信もしておらず、
その条件を踏むきっかけがそもそも生じない。ここが設計の芯で、崩すと全部崩れる。

だから、次の線は何があっても越えない。

- 問題文・図・表を、そのままも、書き写しも、言い換えも、画像も載せない
- 大学の公式解答・出題意図、予備校や問題集の解答解説を引用も要約もしない
- 解説を書くときに読むのは**実物の問題そのもの**だけ。他社の解答解説は見ない
- 問題 PDF を `public/` へ写さない。iframe で外部ページを埋め込まない
- 大学が公表していない配点・採点基準・難易度を、公式の情報として出さない

### リンク

- 大学自身が問題を公開している年度 … そのページへふつうの文字リンク（`kind: "official"`）
- 公開していない年度 … **リンクを張らない**（`kind: "none"`）。赤本などで見てもらう
- 問題を転載している非公式サイトへはリンクしない。型としても用意していないので、
  足したくなったら `types.ts` の `Source` から考え直すこと

`npm run check:html` が、問題へのリンク先が `*.ac.jp` 以外になっていないかを毎回見る。

### ファイルの分かれ方

| ファイル | 中身 |
| --- | --- |
| `lib/solutions/types.ts` | 型と、公開状態・内部の確認記録の定義 |
| `lib/solutions/sources.ts` | 問題の見てもらい方（slug → 年度 → 公式リンク or なし） |
| `lib/solutions/<slug>-<year>.ts` | 解説の中身 |
| `lib/solutions/index.ts` | 公開してよいものだけを選り分ける。ページと sitemap はここだけを見る |
| `app/kaisetsu/policy/` | 掲載方針（読者向けに、上の考え方を書いたページ） |

`publishable()` が公開条件を1か所に集めている。`status` が `published` でも、
原典が未確認・権利面の保留が残っている・公開前の作業が残っているものは外に出ない。
`review`（内部の確認記録）は画面に出さない。

### 解説を1つ足すとき

1. **実物の問題冊子**にあたり、大学・年度・科目・日程・区分・大問番号を照合する
2. `lib/solutions/sources.ts` に、公式の公開先があればリンクを、なければ `kind: "none"` を書く
3. `lib/solutions/<slug>-<year>.ts` を作り、自分で解いて書く
4. `scripts/verify-solutions.py` に、**別の方法で同じ答えに着く**確認を足す
5. `npm run check:solutions` → `npm run build` → `npm run check:html`

### 手元の資料の見分け方

ホームディレクトリには2種類の PDF がある。**混ぜると設計が崩れるので必ず見分ける。**

| 使う | `<大学名>数学<年度>.pdf` など | 実物の入試問題冊子のスキャン。画像で、文字は取れない。これが原典 |
| 使わない | `◯◯大学 YYYY年度 数学解答｜東進…pdf` | 他社（ナガセ）の解答ページを印刷したもの |
| 使わない | `…｜旺文社 入試正解デジタル.pdf`、`解答.pdf`、`解答解説.pdf` | 他社の解答解説 |

### 分かっていること（2026-10-05 時点）

- 公式に問題を公開している大学でも、載っているのは**直近1〜3年度分**であることが多い。
  2019年度まで遡れる大学は見つかっていない
- 名古屋大学は令和8年度しか残っておらず、令和7・令和6年度は目次にリンクがあるまま 404
- 確認できた公式の公開先 … 名古屋大（令和8）、京都大（令和7・8）、九州大（2025・2026）、大阪大（令和8）

## 注意

- 出題形式・分野構成の分析であり、問題文は転載していない。
- 各大学とは無関係の非公式サイト。
- 分析年数は大学によって3〜9年分と幅がある。サイトの文言に「過去8年」と
  決め打ちしないこと（`yearLabel` / `siteTotals` を通す）。
- 価格・ページ数・収録回数・別解の有無も本ごとに違う。文言に直接書かず、
  `data/books.json` と `analysis.json` の値を使うこと。
- 試し読みは「立ち読み」の範囲にとどめる。1回分・1章分をまとめて出さない。
  「無料演習」「無料模試」といった言い方はしない。
- 過去問の解説に、問題文・図・表を載せない。他社の解答解説を言い換えない。
  原典が確認できない年度はページを作らない（`/kaisetsu` の節を参照）。
- 原稿の独自命令（`\probref` など）は `lib/katex-macros.json` に足す。
  足し忘れると画面に命令がそのまま出るので、`npm run check` が実際に組んで確かめている。
